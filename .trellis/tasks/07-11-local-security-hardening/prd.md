# 本地安全与稳定性加固

## Goal

仅在本地仓库修复审计确认的高风险安全、跨用户数据隔离、不可逆清理、SSRF/OOM 与关键稳定性问题；不修改或重启生产环境，由用户后续自行拉取代码上线。

## Requirements

* 不再信任客户端传入的 `x-user-id`，业务身份必须来自有效 session 或显式本地超管模式。
* `/api/cleanup` 不再是公共路径；清理预览和执行必须具有管理员权限，并使用同一组不可变日期条件。
* 清理、收藏案例、任务输入素材等操作必须按 userId 隔离。
* 生产环境认证配置缺失或非法时 fail closed，禁止隐式进入 super-admin。
* 姿势 URL 与远程图片下载阻断内网、环回、链路本地、危险重定向，并限制响应大小。
* 本地文件上传设置硬大小上限，并在进入 Buffer/Base64 前拒绝超限请求。
* OSS 健康探针失败时健康接口返回失败状态，使看门狗能够识别。
* 修复 OSS 重建脚本语法错误；辅助 JSON store 使用原子写入并保留损坏现场。
* 修复清理条件竞态、任务轮询乱序、收藏更新竞态及收藏案例错误任务绑定等高风险前端问题。

## Acceptance Criteria

* [ ] 伪造 `x-user-id` 且无有效 session 时业务 API 返回 401。
* [ ] 普通用户不能执行全局 cleanup，也不能读取或引用其他用户资产。
* [ ] cleanup 删除范围与用户最后确认的预览范围完全一致。
* [ ] 私网、环回、IPv6 私网或重定向到私网的远程 URL 被拒绝。
* [ ] 超限上传与超限远程响应在内存放大前终止。
* [ ] OSS 探针失败时 `/api/health` 返回非 2xx 且 `ok=false`。
* [ ] ESLint、TypeScript、生产构建和新增回归测试通过。
* [ ] 不执行生产 SSH 写操作、部署、PM2/Nginx 操作或 Git 提交。

## Definition of Done

* 高危修复有自动化回归测试或可重复的静态/接口验证。
* 不覆盖已有用户工作区修改。
* 输出上线前备份、环境变量和回滚检查清单。

## Technical Approach

分三个独立区域实施：认证与清理；后端数据隔离及输入安全；前端竞态与运维可靠性。身份解析统一以 session 为可信来源，cleanup 使用管理员授权和服务端预览令牌/条件快照；远程资源统一经过安全 URL 解析、逐跳校验与字节上限。

## Out of Scope

* 本次不把 JSON store 整体迁移到数据库或队列。
* 不实施真正的多实例蓝绿发布架构。
* 不修改生产服务器或生产数据。
* 不执行 Git commit、push 或分支操作。

## Technical Notes

* 生产当前为 `STORAGE_MODE=oss`、`LOCAL_AUTH_MODE=password`，但应用仍受外部身份头伪造影响。
* 生产健康接口已出现 OSS probe error 但仍返回 `ok=true` 的实际故障。
* 本地与生产均有未提交改动，实施必须限定路径并避免覆盖。
