# 姿势裂变真实链路调整

## 目标

沿现有“前端任务参数 → 服务端标准化 → 单姿势 Prompt → Provider 透传”链路，增加下半身主图手臂裁切状态，并重写姿势迁移、背景、构图和道具规则。

## 产品规则

- 仅服务儿童童装姿势。
- 下半身姿势中，主图裁切是手臂能否进入画面的硬门槛：
  - `hidden`：主图完全不露手臂，结果必须保持不露手臂，即使姿势图有手。
  - `visible`：主图允许露手臂，由姿势图决定手是否出现、数量、位置和动作。
- 默认 `hidden`；历史任务缺失字段时也按 `hidden`。
- 主图背景保持不变，只允许必要裁切、人物位置调整和有限扩图。
- 姿势图仅贡献姿势和动作相关道具：椅子、凳子、台阶等支撑道具可迁移；`hidden` 时舍弃依赖手部的道具。
- 上半身迁移保留下半身整体站位和腿部动作，仅允许为真实重心做最小髋、膝、踝联动。

## 实现范围

- `PoseFissionParams` 增加 `lowerBodyMainArmVisibility: 'hidden' | 'visible'`，新任务显式提交，服务端兼容旧任务。
- 姿势裂变表单仅在选中下半身姿势时显示“主图是否露手臂”，默认不露手臂。
- 重构单姿势 Prompt，消除背景冲突，按 full/upper/lower 和手臂裁切状态分流。
- 按实际图片顺序构建 Prompt 角色说明与 `inputImageLabels`；Gemini 使用标签，其他模型继续依赖顺序说明。
- 保持每个姿势一次 `count: 1` 调用、Provider 调度、故障切换和最终 Prompt 持久化不变。

## 非目标

- 不增加姿势库手部或道具元数据。
- 不自动识别主图是否露手臂。
- 不修改各 Provider 的协议、调度和故障切换。
- 不引入新的测试框架。

## 验收标准

- 新任务参数完整，旧任务/重跑缺字段时默认 `hidden`。
- 无细节图时 Prompt 正确说明 2 张图；有正反细节图时正确说明 4 张图。
- `hidden` 明确锁定主图上边界、禁止生成手臂并舍弃手部道具。
- `visible` 明确由姿势图决定手部出现和动作。
- 背景只以主图为准；白底主图加木椅姿势应得到白底加木椅。
- Gemini 图片标签顺序与图片一致；GPT Image/Seedream 图片数组顺序不变。
- `pnpm lint` 与 `pnpm build` 通过。
