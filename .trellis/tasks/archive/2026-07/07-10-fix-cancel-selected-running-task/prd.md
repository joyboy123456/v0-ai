# 修复并行任务只能取消最新任务

## 背景

服装大片裂变允许同时发起多个任务。后端为每个任务维护独立的 `AbortController`，取消接口也支持按任意 `taskId` 取消；但历史页的实时任务面板固定选择当前功能的最新任务。用户点击较早的运行任务时，只更新了 `activeTaskId` 和选中样式，实时面板仍停留在最新任务，导致旧任务没有取消入口。

## 目标

- 历史页优先把当前用户选中的、属于当前功能的任务作为 `visibleTask`。
- 用户点击任意仍在 `pending` / `running` 状态的可取消服装裂变任务后，该任务进入实时面板并显示取消按钮。
- 新任务创建后仍自动成为当前选中任务，并保持现有实时进度体验。
- 不改变后端取消接口和任务执行逻辑。

## 非目标

- 不扩展 AI 服装大片或姿势裂变的取消能力。
- 不重新设计整个历史记录页面。
- 不修改 README 或处理工作区中已有的无关改动。
- 不执行 git commit、push 或历史重写。

## 验收标准

- 同时存在任务 A、B 时，点击运行中的 A，实时面板切换到 A，取消按钮调用 A 的 `taskId`。
- 点击运行中的 B，实时面板切换到 B，取消按钮调用 B 的 `taskId`。
- 未选择当前功能任务时，仍回退展示当前功能的最新任务。
- 选择其他功能的任务不会错误覆盖当前功能的实时任务。
- TypeScript/ESLint 检查通过，相关代码没有格式错误。
