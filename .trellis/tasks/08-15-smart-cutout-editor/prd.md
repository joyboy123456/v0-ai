# 智能抠图编辑器 PRD

## 1. 文档信息

| 项目   | 内容                               |
| ---- | -------------------------------- |
| 产品名称 | 智能抠图编辑器                          |
| 产品定位 | 提供与绘蛙智能抠图功能相近的图片选区、蒙版修正和透明图层导出能力 |
| 目标用户 | 电商运营、设计师、服装商家、AIGC 图片创作者         |
| 上游能力 | 阿里图片分层、智能分割、选区编辑相关 API           |
| 文档版本 | V1.0                             |
| 优先级  | P0                               |
| 交付形态 | Web 端全屏或大尺寸弹窗编辑器                 |

---

# 2. 项目背景

当前平台已经接入阿里的图片分层 API，上游供应商提供了智能分割、增加选区、减少选区、手动涂抹、手动擦除、反选等能力。

现阶段需要在平台中实现一套完整的智能抠图编辑器，功能和交互参考绘蛙的抠图页面。

用户上传图片后，可以：

1. 智能识别图片中的人物、服装、商品或其他对象。
2. 点击图片中的对象，将该对象加入选区。
3. 点击误选区域，将其从选区中移除。
4. 使用画笔补充遗漏区域。
5. 使用橡皮擦删除多余区域。
6. 在右侧实时查看透明图层效果。
7. 完成后导出透明 PNG 和 Mask。

本项目不负责自研图像分割模型，主要负责：

* 前端编辑器交互；
* 上游 API 编排；
* Mask 状态管理；
* 原图与结果预览；
* 透明图层输出；
* 异常处理与任务状态管理。

---

# 3. 产品目标

## 3.1 核心目标

实现一套低学习成本的智能抠图工具，让用户不需要使用 Photoshop，也能快速从图片中提取服装、人物、商品或其他目标对象。

用户应当能够通过：

* 智能点击；
* 自动选区；
* 增加选区；
* 减少选区；
* 涂抹选区；
* 擦除选区；

完成较为精确的图片分层。

---

## 3.2 体验目标

用户进入编辑器后，应当在较短时间内完成以下流程：

> 上传图片 → 智能分析 → 点击目标 → 修正选区 → 查看透明结果 → 完成导出

对于轮廓清晰的服装、人物或商品，目标是用户通过 1～3 次操作即可完成抠图。

对于人物手臂遮挡服装、服装与背景颜色接近等复杂情况，允许用户通过手动画笔进行修正。

---

## 3.3 成功标准

| 指标               | 目标         |
| ---------------- | ---------- |
| 智能抠图任务成功率        | ≥ 98%      |
| 普通图片首次选区可用率      | ≥ 85%      |
| 用户完成抠图平均操作次数     | ≤ 5 次      |
| 透明图层尺寸准确率        | 100% 与原图一致 |
| 选区编辑撤销恢复准确率      | 100%       |
| 用户完成率            | ≥ 80%      |
| 普通 2048px 图片准备时间 | P95 ≤ 8 秒  |
| 单次智能增减选区响应时间     | P95 ≤ 4 秒  |

以上性能目标为产品目标，最终需要结合阿里上游 API 的实际响应速度进行调整。

# 5. 用户使用场景

## 5.1 服装提取

用户上传一张模特穿搭图片，希望只提取模特身上的上衣或裤子，用于后续换装、商品展示或图片生成。

例如：

* 只提取上衣；
* 只提取裤子；
* 提取整套服装；
* 去除人物皮肤；
* 去除头发；
* 去除背景。

---

## 5.2 商品提取

用户上传商品实拍图，希望提取商品主体并去掉背景。

例如：

* 提取鞋子；
* 提取包包；
* 提取化妆品瓶；
* 提取家具；
* 提取货架；
* 提取多个相连的商品区域。

---

## 5.3 人物提取

用户希望保留完整人物，去除天空、草地、墙面等背景内容。

---

## 5.4 局部素材提取

用户希望提取图片中的某个局部对象，用于后续素材合成。

例如：

* 只提取帽子；
* 只提取腰带；
* 只提取鞋子；
* 只提取手提包。

# 7. 页面整体结构

编辑器以全屏弹窗或接近全屏的大尺寸弹窗形式展示。

页面由以下区域组成：

1. 顶部工具栏；
2. 左侧原图编辑区；
3. 右侧透明结果预览区；
4. 最右侧操作技巧区；
5. 底部画布控制区；
6. 右下角完成按钮；
7. 右上角关闭按钮。

---

参考比例：

| 区域      | 建议宽度       |
| ------- | ---------- |
| 左侧原图编辑区 | 主编辑区约 42%  |
| 右侧结果预览区 | 主编辑区约 42%  |

# 8. 页面功能结构

## 8.1 顶部工具栏

顶部工具栏包含：

* 编辑选区标题；
* 涂抹选区；
* 擦除选区；
* 自动选区；
* 增加选区；
* 减少选区；
* 反选选区；
* 笔刷大小；
* 关闭按钮。

工具采用互斥模式。

同一时间只能有一个主要编辑工具处于激活状态。

例如：

* 激活增加选区时，不能同时激活减少选区；
* 激活涂抹选区时，不能同时激活擦除选区。

---

## 8.2 左侧原图编辑区

左侧展示原始图片。

当前选中的区域需要覆盖半透明蓝色蒙版。

建议蒙版颜色：

* 蓝色；
* 透明度 30%～45%。

用户需要能够通过蒙版明确识别当前保留的范围。

左侧画布支持：

* 点击；
* 拖动画笔；
* 缩放；
* 平移；
* 显示点击点；
* 显示笔刷范围；
* 显示加载状态。

---

## 8.3 右侧结果预览区

右侧展示当前选区对应的透明图层。

规则如下：

* 选中区域显示原图像素；
* 未选中区域完全透明；
* 透明区域显示棋盘格背景；
* 右侧图层位置、缩放比例与左侧保持同步；
* 用户每次修改选区后，右侧结果立即更新。

右侧预览不得重新生成图片。

右侧显示的内容必须直接来源于：

> 原图像素 × 当前 Mask

不能改变原图颜色、纹理、尺寸和清晰度。

---

## 8.4 操作技巧区

最右侧展示固定帮助信息。

包含：

### 抠图小技巧

根据当前选中的工具，动态展示对应提示。

增加选区：

> 点击需要保留的地方。

减少选区：

> 点击不需要保留的地方。

涂抹选区：

> 涂抹需要保留的区域。

擦除选区：

> 擦除不需要的区域。

### 正确案例

展示：

> 抠图准确 → 后续使用效果较好。

### 错误案例

展示：

> 抠图不准确 → 后续使用效果较差。

帮助区图片应使用平台自己的素材，不直接复用绘蛙的品牌图片。

# 9. 核心操作流程

## 9.1 进入编辑器

用户在图片页面点击：

* 智能抠图；
* 图片分层；
* 提取主体；

进入抠图编辑器。

系统需要携带：

* 图片 ID；
* 原图地址；
* 原图宽度；
* 原图高度；
* 当前业务场景。

业务场景可以包括：

* garment：服装；
* person：人物；
* product：商品；
* general：通用对象。

服装业务默认传递：

> garment

便于上游接口优先识别衣服，而不是人物或背景。

---

## 9.2 智能抠图准备

进入页面后，系统立即调用阿里上游接口创建抠图任务或分割会话。

准备阶段左侧图片显示半透明遮罩，并展示：

> 智能抠图准备中……

同时展示加载图标。

准备期间：

* 所有编辑工具禁用；
* 完成按钮禁用；
* 允许关闭页面；
* 不允许提交点击或画笔操作。

准备成功后：

* 去除遮罩；
* 默认激活“增加选区”；
* 鼠标移动到图片上时显示可点击状态；
* 展示提示“点击需要保留的区域”。

---

## 9.3 自动选区

用户点击“自动选区”后，系统调用自动分割能力。

默认策略：

* 服装场景优先识别服装；
* 人物场景优先识别完整人物；
* 商品场景优先识别主要商品；
* 通用场景优先识别画面中的主要前景。

自动选区成功后：

* 左侧显示蓝色蒙版；
* 右侧显示透明图层；
* 完成按钮变为可用；
* 记录一次可撤销操作。

若图片中存在多个主要对象，上游返回多个候选区域时，优先选择置信度最高的主要区域。

后续版本可增加候选对象选择，本期不要求。

---

# 10. 增加选区

## 10.1 功能定义

增加选区不是普通画笔。

增加选区属于智能语义选择。

用户点击图片中的某个位置后，系统应当尽量识别该位置对应的完整对象或完整语义区域。

例如：

* 点击上衣中间，应选择完整上衣；
* 点击裤子，应选择完整裤子；
* 点击鞋子，应选择完整鞋子；
* 点击商品瓶身，应选择完整商品。

不能只增加点击位置附近的一小块圆形区域。

---

## 10.2 操作流程

1. 用户点击“增加选区”；
2. 按钮显示蓝色激活状态；
3. 鼠标进入图片后显示十字光标或点击光标；
4. 用户点击目标位置；
5. 页面显示点击点；
6. 调用上游智能分割接口；
7. 接口返回新的候选 Mask；
8. 将候选 Mask 合并到当前选区；
9. 左右画布同步更新；
10. 生成一条撤销记录。

---

## 10.3 合并规则

最终选区不能简单使用最新接口结果覆盖旧结果。

应采用合并逻辑：

> 当前 Mask + 新增 Mask

即：

> finalMask = currentMask ∪ addedMask

若用户之前手动擦除过某些区域，新增智能选区不能无条件恢复这些已经擦除的区域。

建议分别维护：

* semanticMask：智能语义选区；
* manualAddMask：手动涂抹增加区域；
* manualEraseMask：手动擦除区域。

最终结果：

> finalMask = (semanticMask ∪ manualAddMask) − manualEraseMask

---

# 11. 减少选区

## 11.1 功能定义

减少选区用于通过智能识别删除不需要的完整对象或语义区域。

例如：

* 衣服选区中误选了手臂；
* 商品选区中误选了桌面；
* 人物选区中误选了旁边的人；
* 裤子选区中误选了草地阴影。

---

## 11.2 操作流程

1. 用户点击“减少选区”；
2. 按钮显示红色激活状态；
3. 用户点击不需要保留的位置；
4. 调用上游接口提交负向点击点；
5. 上游返回待移除的区域或修正后的 Mask；
6. 从当前选区中移除该区域；
7. 左右画布同步更新；
8. 生成一条撤销记录。

减少逻辑：

> finalMask = currentMask − removedMask

若减少后选区为空：

* 右侧只显示透明棋盘格；
* 完成按钮禁用；
* 提示“当前选区为空，请重新选择需要保留的区域”。

---

# 12. 涂抹选区

## 12.1 功能定义

涂抹选区用于手动补充智能识别遗漏的小区域。

典型场景：

* 衣服边角遗漏；
* 腰带未识别；
* 细肩带未识别；
* 裤脚缺失；
* 袖口缺失；
* 商品小配件遗漏；
* 透明或反光物体边缘遗漏。

---

## 12.2 交互要求

用户选择“涂抹选区”后：

* 展示笔刷大小调节滑杆；
* 鼠标显示圆形笔刷范围；
* 按下鼠标后可以连续涂抹；
* 涂抹轨迹实时显示为半透明蓝色；
* 右侧结果实时显示涂抹区域中的原图内容。

画笔拖动过程中应使用前端本地 Mask 实时更新，不应每移动一个像素就请求上游接口。

鼠标松开后：

* 将本次完整笔画保存为一次历史记录；
* 根据需要将完整笔画一次性发送给后端；
* 避免产生大量 API 请求。

---

## 12.3 涂抹规则

涂抹选区属于像素级操作，不进行语义扩展。

用户画到哪里，就增加哪里。

计算逻辑：

> manualAddMask = manualAddMask ∪ strokeMask

---

# 13. 擦除选区

## 13.1 功能定义

擦除选区用于手动删除多余区域。

典型场景：

* 手臂被误选；
* 皮肤被误选；
* 头发被误选；
* 背景被误选；
* 衣服中间的镂空区域被错误填充；
* 商品周围存在背景残留。

---

## 13.2 交互要求

用户选择“擦除选区”后：

* 展示笔刷大小；
* 鼠标显示圆形橡皮擦范围；
* 拖动过程中实时删除选区；
* 左侧蓝色蒙版实时消失；
* 右侧对应区域实时变为透明。

鼠标松开后，将本次擦除保存为一条历史记录。

擦除逻辑：

> manualEraseMask = manualEraseMask ∪ eraseStrokeMask

---

# 14. 笔刷大小

笔刷大小仅在以下工具激活时展示：

* 涂抹选区；
* 擦除选区。

建议范围：

* 最小值：5px；
* 最大值：200px；
* 默认值：40px。

笔刷尺寸应以原图坐标为标准。

用户缩放画布后，视觉上的笔刷圆圈需要跟随缩放，但实际修改范围应准确映射到原图像素。

例如：

原图坐标下 40px 的笔刷，在画布缩放到 50% 时，屏幕上显示为 20px。

---

# 15. 反选选区

用户点击“反选选区”后：

* 当前选中区域变为透明；
* 当前透明区域变为选中；
* 左侧蒙版立即更新；
* 右侧透明图层立即更新；
* 生成一条撤销记录。

计算规则：

> finalMask = 1 − finalMask

反选后不需要调用智能分割模型，可以在前端或后端直接计算。

---

# 16. 双画布同步

左侧原图画布和右侧结果画布必须保持以下内容同步：

* 图片缩放比例；
* 图片显示位置；
* 平移偏移；
* 旋转方向；
* 图片宽高比；
* 画布中心点。

用户缩放左侧图片时，右侧必须同步缩放。

用户拖动左侧图片时，右侧必须同步移动。

不能出现：

* 左侧显示人物上半身；
* 右侧显示人物下半身；

这种视口不一致的问题。

---

# 17. 缩放与画布控制

底部工具栏包含：

* 适应画布；
* 拖动画布；
* 缩小；
* 当前缩放百分比；
* 放大；
* 撤销；
* 重做；
* 重置。

---

## 17.1 适应画布

点击后将图片完整展示在当前画布内。

保证：

* 图片不被裁切；
* 图片居中；
* 左右画布同步；
* 保持原图宽高比。

---

## 17.2 拖动画布

用户可以通过以下方式移动画布：

* 点击拖动工具后拖动；
* 按住空格键拖动；
* 鼠标中键拖动。

拖动画布不能修改选区。

---

## 17.3 缩放

缩放范围建议：

* 最小：10%；
* 最大：800%。

每次点击加减按钮调整 10%。

支持鼠标滚轮缩放。

滚轮缩放时，应以鼠标所在位置为缩放中心。

---

# 18. 撤销、重做与重置

## 18.1 撤销

以下每个动作均生成一条历史记录：

* 自动选区；
* 增加选区；
* 减少选区；
* 一次完整涂抹；
* 一次完整擦除；
* 反选；
* 重置。

连续画笔移动只记录为一个操作，不按每个移动点分别记录。

建议最多保留最近 30～50 条历史记录。

---

## 18.2 重做

撤销后允许恢复被撤销的操作。

用户执行新的编辑动作后，清空重做栈。

---

## 18.3 重置

点击重置后恢复到：

* 初始无选区状态；

或：

* 自动选区后的初始状态。

推荐本期恢复到“无选区状态”。

重置需要作为一条可撤销操作，不直接清空全部历史。

---

# 19. 完成与导出

## 19.1 完成按钮状态

以下情况下完成按钮禁用：

* 智能抠图仍在准备；
* 当前选区为空；
* 正在处理选区；
* 正在导出；
* 原图加载失败。

选区存在且当前没有任务运行时，完成按钮可用。

---

## 19.2 完成操作

用户点击“完成”后：

1. 锁定编辑操作；
2. 按钮显示加载状态；
3. 生成最终 Mask；
4. 使用原图和 Mask 生成透明 PNG；
5. 上传结果文件；
6. 保存抠图任务记录；
7. 将结果返回上一级页面；
8. 关闭编辑器。

---

## 19.3 输出内容

至少返回以下内容：

| 字段                  | 说明        |
| ------------------- | ----------- |
| originalImageUrl    | 原图地址      |
| transparentImageUrl | 透明 PNG 地址 |
| maskUrl             | Mask 地址   |
| width               | 原图宽度      |
| height              | 原图高度      |
| boundingBox         | 选区最小外接矩形  |
| sessionId           | 抠图会话 ID   |
| resultId            | 最终结果 ID   |
| createdAt           | 创建时间      |

透明 PNG 要求：

* PNG 格式；
* RGBA；
* 保留 Alpha 通道；
* 尺寸与原图完全一致；
* 未选区域 Alpha 为 0；
* 选中区域 RGB 不得改变；
* 不得重新压缩导致明显色差；
* 不得裁切到对象边界。

Mask 要求：

* 尺寸与原图完全一致；
* 支持黑白 PNG 或单通道 Alpha；
* 白色代表保留；
* 黑色代表透明；
* 如上游为相反规则，后端需要统一转换。

# 20. 关闭编辑器

用户点击右上角关闭按钮时：

如果用户没有进行任何编辑，直接关闭。

如果用户已经产生选区或修改，需要提示：

> 当前抠图结果尚未保存，确认退出吗？

按钮：

* 继续编辑；
* 放弃并退出。

关闭页面不能自动覆盖原图。

# 23. 上游 API 适配设计

建议后端增加统一的供应商适配层。

前端不直接感知供应商是阿里、火山或其他平台。

统一能力包括：

| ---- | -------------------- |
| 创建会话 | 图片上传、图片分析、创建分割任务     |
| 自动选区 | 自动主体分割、图片分层          |
| 增加选区 | 正向点提示、正向区域提示         |
| 减少选区 | 负向点提示、排除区域提示         |

| 擦除选区 | 手动 Erase Mask        |
| 反选   | 本地 Mask 反转           |

* createCutoutSession；

* addSelection；
* subtractSelection；
* applyBrushMask；
* invertMask；
* exportCutout；
* getCutoutSession。

即使后续更换供应商，前端接口也不需要改变。

返回信息：

* sessionId；
* normalizedImageUrl；
* width；
* height；
* capabilities；

请求信息：

* sessionId；
* operation；

* pointY；
* baseMaskId；
* requestVersion；
* scene。

operation 包括：

* add；

坐标必须使用原图坐标，而不是屏幕坐标。

请求信息：

画笔轨迹建议使用点数组或前端生成的局部 Mask 上传。

## 24.4 导出结果

* maskUrl；

* height；
* boundingBox。

# 25. 坐标转换要求

画布上的点击坐标必须准确转换成原图坐标。

需要考虑：

* 页面缩放；
* Canvas 缩放；
* 图片平移；
* 图片留白；
* 浏览器缩放；
* 设备像素比；
* 原图 EXIF 方向；
* 图片预览尺寸与原始尺寸差异。

坐标计算完成后需限制在：

* X：0 至 imageWidth；
* Y：0 至 imageHeight。

禁止将画布容器坐标直接提交给上游 API。

---

# 26. 请求并发与版本控制

用户可能快速连续点击不同区域。

系统必须避免旧请求覆盖新结果。

每次请求携带递增的：

> requestVersion

前端只接受当前最新版本的响应。

例如：

* 请求 10 尚未返回；
* 用户又提交请求 11；
* 请求 11 先返回；
* 请求 10 后返回；

此时必须丢弃请求 10 的结果，不能覆盖请求 11。

建议同一会话中的智能增减操作采用队列执行，或者使用 Latest Request Wins 策略。

---

# 27. 性能要求

## 27.1 前端性能

* 画笔绘制帧率目标不低于 30 FPS；
* 鼠标拖动过程中不得出现明显卡顿；
* 本地 Mask 更新目标延迟低于 100ms；
* 画笔轨迹需要进行采样和简化；
* 不得每次 pointermove 都请求服务器；
* 大图使用预览图进行 Canvas 编辑；
* 最终导出使用原图尺寸 Mask。

---

## 27.2 图片处理

支持格式：

* JPG；
* JPEG；
* PNG；
* WebP。

建议限制：

* 单张图片最大 20MB；
* 最长边不超过 8192px；
* 最小尺寸不低于 256×256px。

具体限制以阿里上游接口为准。

若原图过大：

* 前端使用缩略图编辑；
* 后端保持原图；
* 最终 Mask 映射回原图尺寸；
* 输出结果仍保持原图尺寸。

---

# 28. 边缘质量要求

抠图结果需要重点检查：

* 衣服轮廓；
* 袖口；
* 裤脚；
* 衣领；
* 腰带；
* 肩带；
* 商品边缘；
* 镂空区域；
* 人物与衣服接触位置。

避免出现：

* 明显锯齿；
* 黑边；
* 白边；
* 背景残留；
* 皮肤残留；
* 边缘缺失；
* 大面积毛边；
* 透明区域被错误填充。

对于人物手臂遮挡服装的情况，只保留原图中真实可见的服装像素。

本期不对被遮挡的衣服区域进行 AI 补全。

---

# 29. 降级策略

当智能选区 API 不可用时，系统仍应允许用户使用：

* 涂抹选区；
* 擦除选区；
* 反选；
* 撤销；
* 导出。

即智能选区失败不能导致整个编辑器完全不可用。

提示：

> 智能识别暂时不可用，仍可以使用画笔手动完成选区。

---

# 30. 数据保存

抠图过程中建议保存以下数据：

* sessionId；
* 原图地址；
* 当前 Mask ID；
* 操作历史；
* 最后编辑时间；
* 上游任务 ID；
* 当前请求版本；
* 导出结果地址；
* 错误信息。

临时会话可以设置有效期。

建议未完成会话保留 24 小时，具体时间根据存储成本决定。

# 32. 验收用例

## 用例一：增加裤子选区

测试图片：

一名模特穿着上衣和短裤站在草地上。

操作：

1. 进入编辑器；
2. 等待智能准备完成；
3. 激活增加选区；
4. 点击短裤。

预期：

* 短裤整体被选中；
* 左侧短裤出现蓝色蒙版；
* 右侧显示透明背景下的短裤；
* 不应大量选中草地、腿部或鞋子。

---

## 用例二：继续增加上衣

操作：

1. 在已有裤子选区的情况下；
2. 点击上衣。

预期：

* 原有裤子选区保留；
* 上衣被加入选区；
* 右侧同时显示上衣和裤子；
* 不能用新结果覆盖掉原有裤子。

---

## 用例三：删除人物皮肤

操作：

1. 激活减少选区；
2. 点击误选的手臂或皮肤。

预期：

* 被点击的皮肤区域从选区中移除；
* 服装主体仍然保留；
* 右侧对应皮肤区域变为透明。

---

## 用例四：手动补充腰带

操作：

1. 激活涂抹选区；
2. 缩小笔刷；
3. 涂抹遗漏的腰带区域。

预期：

* 涂抹区域立即加入选区；
* 右侧实时显示腰带；
* 鼠标松开后只产生一条撤销记录。

---

## 用例五：擦除背景残留

操作：

1. 激活擦除选区；
2. 擦除误选的草地。

预期：

* 草地从选区中删除；
* 右侧对应区域变为透明；
* 不影响周围服装区域。

---

## 用例六：撤销与重做

操作：

1. 完成一次涂抹；
2. 点击撤销；
3. 点击重做。

预期：

* 撤销后完整恢复到操作前；
* 重做后完整恢复涂抹结果；
* Mask 不出现偏移或模糊。

---

## 用例七：缩放后点击

操作：

1. 将图片放大到 200%；
2. 平移图片；
3. 点击衣服边缘。

预期：

* 提交给接口的坐标准确；
* 选区位置与用户点击位置一致；
* 左右画布缩放与位置一致。

---

## 用例八：反选

操作：

1. 选中人物；
2. 点击反选。

预期：

* 人物变为透明；
* 背景变为选区；
* 左右画布立即更新；
* 支持撤销。

---

## 用例九：导出透明图层

操作：

1. 完成选区；
2. 点击完成。

预期：

* 生成透明 PNG；
* 图片尺寸与原图一致；
* 选中区域颜色与原图一致；
* 未选区域完全透明；
* 同时生成 Mask；
* 返回上一级页面。

---

## 用例十：接口失败

操作：

1. 模拟智能选区 API 超时。

预期：

* 不清空已有 Mask；
* 不关闭编辑器；
* 显示错误提示；
* 允许重新点击；
* 允许使用手动画笔继续编辑。

6. 旧请求结果不得覆盖新请求结果。
7. 涂抹和擦除必须前端实时响应。
8. 智能识别失败时，手动编辑仍然可用。
9. 完成前不得破坏或覆盖原始图片。
10. 输出图片必须保留原始分辨率和透明通道。

# 38. 上游能力调研结论（2026-08-15，详见 research/aliyun-interactive-segmentation.md）

- **阿里云交互式分割 API 已下架**：InteractiveFullSegmentation / InteractiveScribbleSegmentation 属 aigen 创新专区，2025-08-14 停止新开通、2025-10-14 下架，现不可用；imageseg 类目全部是一键式 API，**无任何点选/涂抹交互入参**。
- **自动分割沿用现有 imageseg**：SegmentCommonImage（主体）、SegmentCloth（上装/下装）、可扩展 SegmentBody/SegmentCommodity。
- **交互修正需引入开源 SAM2**：正负点（point_coords/point_labels）、mask_input 有状态修正，坐标用原图像素；部署形态待确认（托管 API ~$0.011/次 vs GPU 自托管）。
- **边缘细化 RefineMask（0.007 元/次）**：可选，建议 P1。
- **反选/位运算合并/涂抹擦除/导出合成**：客户端零成本完成，不请求模型。
- 阿里云无「图片分层」API；Qwen-Image-Layered（开源）是多图层拆分的专门解，属 P2（本期 §4.2 明确不做多图层拆分）。

# 39. 方案定稿：P0「服饰智能分层」（类绘蛙，零新依赖，2026-08-15 用户确认）

> 用户拍板采用**方案一**：只做服饰场景下的"类绘蛙"交互，不承诺任意对象智能分层。
> P0 功能名：**服饰智能分层**（别名：服饰智能选区）。

## 39.1 进入编辑器（按场景准备，不无脑全调）

用户上传图片后显示「智能抠图准备中……」，后端按业务场景调用阿里现役 API：

| 场景 | 调用的阿里 API |
| ---- | ---- |
| 服装分层（garment，默认） | `SegmentCloth` 七类：tops / coat / pants / skirt / shoes / bag / hat（官方 ClothClass 合法值已核实）+ 辅助 `SegmentSkin` `SegmentHair` `SegmentBody` `SegmentCommonImage` |
| 人物抠图（person） | `SegmentBody` / `SegmentHair` / `SegmentSkin`（+ 通用） |
| 商品抠图（product） | `SegmentCommodity` / `SegmentHDCommonImage` |

本期只实现 garment 场景；person/product 场景接口预留。

## 39.2 类别 Mask → 候选区域（浏览器端连通区域分析）

- 阿里返回的是类别整体 Mask（skin=所有皮肤、shoes=所有鞋）。
- 在**浏览器 Web Worker** 里做连通区域分析，把不相连的部分拆成独立候选区域：
  - skin → face / left_arm / right_arm / left_leg / right_leg
  - shoes → left_shoe / right_shoe
- 纯图像连通算法，不是再跑 AI；4 核 8G 可处理，但放在用户设备上分摊压力。
- **索引图** regionIndexMap 最长边控制在 **1024px** 左右（控内存）；每个像素记录所属候选区域 id。
- 若两个区域在 Mask 中粘连，连通分析无法自动拆开 → 由用户用擦除工具修正（能力边界）。

## 39.3 本地候选区域索引

```ts
interface CandidateRegion {
  id: string
  category: 'tops' | 'coat' | 'pants' | 'skirt' | 'shoes' | 'bag' | 'hat' | 'skin' | 'hair' | 'body' | 'common'
  previewMask: ImageBitmap      // 低分辨率预览蒙版
  fullResolutionMaskUrl: string // 全分辨率 Mask（导出用）
  bbox: [number, number, number, number]
  area: number
}
```

## 39.4 悬停交互（不调 API，零延迟）

鼠标移动 → 屏幕坐标转图片坐标 → 读 regionIndexMap 对应像素 → regionId → 该区域预览 Mask → 蓝色遮罩预览。
点击后才正式加入选区；右侧透明预览实时更新。

## 39.5 多 Mask 重叠命中规则

命中优先级：**具体服饰类别 > 皮肤/头发 > 完整人体 > 通用主体**；
同时命中多个区域时，**优先选面积更小、更具体的区域**（避免鼠标在上衣上却高亮整个人）。

## 39.6 能力边界（明确承诺与不承诺）

| 能力 | 是否支持 |
| ---- | ---- |
| 悬停上衣/裤子显示蓝色遮罩、点击加入/减少 | ✅ |
| 涂抹增加选区 / 擦除选区 / 反选（纯前端） | ✅ |
| 右侧实时透明图层预览（双画布同步） | ✅ |
| 最终 Mask 精细化（`RefineMask`，可选） | ✅ |
| 悬停任意未知物体 / 草地中任意小块 | ❌ 不支持 |
| 准确识别所有独立对象 | ❌ 不支持 |
| 完全复刻绘蛙通用智能选区 | ❌ 不支持 |

## 39.7 涂抹/擦除不吃 GPU（已向用户澄清）

涂抹选区、擦除选区、反选、Mask 位运算、撤销重做全部是前端 Canvas 本地像素操作，
零 GPU、零模型、零 API 调用；只有"语义类别分割准备"和可选的 RefineMask 走阿里 API（0.002~0.008 元/次）。
