# 创作助手 Beta（本地验证）

独立新功能页面：`/beta/agent`。首页及其桌面、手机导航均不展示 Agent 或画布入口，通过独立链接访问。首批支持上传参考图、对话准备服饰生图方案、修改提示词后确认生成一张、画布选择与拖动、选中生成结果继续修改，以及会话恢复。

## 启动

沿用项目现有依赖和文本/图片模型配置。在项目目录运行：

```sh
BETA_AGENT_ENABLED=true BETA_AGENT_USERNAMES=user01 pnpm exec next dev --webpack --hostname 127.0.0.1 --port 3037
```

将 `user01` 换成要参与测试的现有登录用户名；多个用户名使用英文逗号分隔。通过 `http://127.0.0.1:3037/beta/agent` 进入，未登录时会跳转到登录页，登录后返回这个独立功能。正常访问首页仍进入原工作台。

- 默认关闭；空白名单拒绝全部用户，管理员也不自动获得权限。
- 页面和每个 Beta API 都在服务端校验登录及白名单。
- `NODE_ENV=production` 时始终关闭，包括误设开关的情况。本版本仅用于本地开发、测试和评估。
- 无论是否开启 Beta，首页都不请求 Beta 权限、不展示 Beta 入口，也不加载画布代码。
- 关闭测试实例，或移除 `BETA_AGENT_ENABLED=true` 后重启，即可关闭入口和所有 Beta API。

## 模型和费用

对话规划复用 `TEXT_LLM_API_KEY`、`TEXT_LLM_BASE_URL`、`TEXT_LLM_MODEL`、`TEXT_LLM_TIMEOUT_MS` 及现有文本模型客户端。图片生成继续使用当前已配置的图片供应商和 `ai-fashion-photo` 工作流。不要将密钥放在浏览器、对话或前端环境变量中。

当前已接入文本 LLM 调用链：LLM 理解需求并输出结构化方案，服务端校验方案，用户确认后执行已接入的生图工具。接入更多平台功能还需要添加对应工具适配；更换 LLM 不会自动增加工具能力。

“准备方案”只调用文本模型；“确认生成”才创建图片任务。文本和图片模型调用都可能产生供应商费用。任务中的历史 credits 元数据并不是新增的用户余额扣减机制。

Beta 每次固定生成一张，额外限制全局一个在途图片任务、每用户每天最多 20 次确认生成（按北京时间统计）。原任务队列的全局、用户和供应商并发限制继续生效。重复确认同一个方案返回原任务；失败后需重新准备方案再确认，查询进度不会重新创建任务。取消后仍会等待底层执行退出才释放 Beta 名额。

文本规划只使用用户描述和明确选中的参考素材信息；首批没有额外的视觉识别服务，不会自动识别商品类别或承诺修复某个局部区域。

## 数据与范围

会话、消息、画布位置和 Beta 执行记录独立保存在 `data/agent-beta/`。图片继续使用现有素材存储，生成任务仍出现在现有任务历史中。会话不会将图片二进制或 base64 写入自身 JSON。

本地开发进程重启后，单图任务不会自动重新生图；可在原工作台核对后取消遗留任务，再准备新方案。若确认记录存在而原任务缺失，Beta 暂停新确认，需先核实或恢复对应任务数据，避免重复消耗。

现有三条工作流的表单入口保持原状。本期 Agent 只接服饰单图生成；服装大片裂变、姿势裂变、任意区域重绘和跨工具自动执行随后按实际测试反馈逐步接入。

## 验证

测试使用可注入的模型、任务与素材依赖，不调用真实付费模型。建议同时检查默认关闭、白名单隔离、重复确认、任务恢复、选图继续修改和移动端布局。

本次验证结果：

- Beta、画布状态、门禁和任务恢复测试 34 项通过；已有抠图/事件路由测试 28 项通过。
- TypeScript、相关 ESLint、`git diff --check` 通过；隔离副本的完整生产构建通过。
- 本地模拟模型端到端验证上传、准备方案、确认生图、结果回写、选图续改和重复确认；准备方案阶段图片请求为 0，重复确认后图片请求仍为 1。
- 浏览器检查桌面与 390px 手机布局、明暗主题、拖动保存和刷新恢复。
- 生产模式误设开关后，Beta 页面及全部业务 API 仍拒绝访问，原工作台任务创建和生成通过。

构建同时修复了既有 Next.js 路由的非法辅助函数导出：将测试工厂原样移到同目录 `handler.ts`，路由只保留运行配置和 HTTP 方法。接口行为及测试逻辑保持不变。
