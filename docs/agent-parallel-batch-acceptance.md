## 交付接口与边界

- B2：`createDeterministicObserver`，依赖注入安全图片读取和可选受控分类；像素/face/分类独立降级。只输出能支持的图像事实，不把“下装”猜成裤子，不凭类别断言平铺。OCR、水印、模糊与风格未检测，明确留作未知说明。
- C1：`ToolRegistry` 只持有元数据；当前仅接受 strict ZodObject 且 catchall 为 ZodNever，拒绝不能验证的包装 schema；没有真实 handler。
- C2：`selectToolFrontier` 先硬权限再裁剪；机械参数待绑定时可以准备 dry-run，真实副作用仍须受控。
- C6：`bindToolProposal` 绑定服务端身份/素材/模型/参数来源；模型只提工具名与 prompt。多张值可保留供预览，不构成提交授权。
- C10：`routeAgentRequest` 是纯规则，证据、机械参数、风险与人工闸门各自计算；110 项开发回归不等于生产准确率承诺。
- C5：`ToolDispatcher` 每实例固定一个用户/会话/消息 turn，只有准入通过才消耗调用名额；付费动作仅返回 preview，vendor 或写动作必须继续 Gateway。本层没有执行 handler 或签发审批凭证。
