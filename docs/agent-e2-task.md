## 范围与验收

1. 人工反馈结构为 verdict（approved/revise/wrong_direction）、七类 issues、可选 note、显式 lockedFacts。不能从“未勾选问题”、自由文本或 E1 SHADOW_PASS 推断认可。仅 wrong_direction 允许重建方向。
2. 新增已鉴权反馈 POST 接口，使用当前 C8 ADMITTED 决定与真实结果成员校验用户、会话、消息、动作、资产，保持 ActionLedger → user-file 锁序。客户端不得自报准入或摘要证据。
3. 反馈写入现有会话存储，旧会话可缺省字段；限制数量与长度。相同提交幂等、同 id 改内容冲突；同一不可变结果不能靠反复点击增加轮次。刷新与重启保留事实。
4. 通过显式 feedbackId 继续，后续结果只有属于该反馈续作的消息才能关联比较，拒绝不相关结果、过期前驱与重复分叉。首次反馈不计算改善；不同后继结果连续两次由用户确认未改善则停止，approved 则完成。wrong_direction 不自动清空停滞计数或锁定事实。
5. 已认可的事实沿链保留；局部修改问题与锁定事实冲突时拒绝。继续规划把反馈作为用户来源数据，不能把 note 提升为系统指令。停止状态必须在任何模型/供应商调用前拦截；预览编辑不能丢弃反馈约束。约束传入预览不等于已证明像素质量。
6. UI 接入实际 AgentChat/hook/workbench，使用语义表单、明确标签、可访问错误提示与持久状态，覆盖移动端与双主题。反馈保存本身不调用模型、生图或批准；继续仍先给预览，由用户另行确认。
7. E1 机器质量展示不在本卡必要范围；若展示，必须同时读取完整记录中的 unsupported 清单，不能仅展示精简 disposition。

验收使用注入端口、合成图片和模拟 API：授权/准入、幂等冲突、链路绑定、重启恢复、锁定事实、两轮停止、预览编辑保护、异步切换与界面显示。独立执行 `test:agent`、非增量 tsc、受影响文件 lint、架构守卫与 diff 检查，并做实际组件浏览器验收。
